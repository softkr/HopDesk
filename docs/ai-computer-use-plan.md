# AI 공동 작업자 개발 계획서

- 작성일: 2026-11-25
- 대상 버전: HopDesk 0.4.0 (현재 0.3.0)
- 상태: 초안 (구현 전)

## 1. 요약

HopDesk로 접속한 원격 화면을 AI가 사람과 함께 조작하는 기능을 추가한다. 사용자가 세션 창의 대화 패널에 작업을 적으면, AI가 원격 화면의 스크린샷을 보고 마우스와 키보드를 조작해 작업을 수행한다. 사람은 언제든 끼어들어 직접 조작하거나 추가로 지시할 수 있다.

AI는 한 회사 제품에 묶지 않는다. Claude, GPT, Gemini와, 이들의 API 형식을 따르는 오픈 모델(로컬 또는 사내 서버)을 모두 쓸 수 있게 한다.

1단계는 **RDP 세션**에서 **Claude 형식**부터 지원하고, 이어서 GPT 형식과 VNC 세션을 붙인다. Gemini 형식은 2단계다. 대화 상대는 세션 창 안에 겹쳐 그리는 **캐릭터와 말풍선**이다(4절).

## 2. 용어

| 용어 | 뜻 |
|---|---|
| computer use | AI 모델이 스크린샷을 입력으로 받아 "여기를 클릭", "이 글자를 입력" 같은 동작을 출력하는 방식 |
| 제공자 | AI 모델을 API로 제공하는 쪽. Anthropic, OpenAI, Google, 또는 오픈 모델을 띄운 서버 |
| 형식 | API 요청·응답의 모양. Claude 형식(Anthropic Messages API), GPT 형식(OpenAI API), Gemini 형식 |
| 어댑터 | 한 형식의 요청·응답을 HopDesk 내부의 공통 동작으로 바꾸는 코드 |
| 전용 도구 모드 | 제공자가 내장한 computer use 도구를 쓰는 방식 |
| 함수 도구 모드 | 같은 동작들을 일반 함수 도구로 직접 정의해 쓰는 방식. 내장 도구가 없는 오픈 모델용 |
| 세션 프로세스 | 연결 하나를 담당하는 `hopdesk connect` 프로세스. 원격 화면 창을 띄운다 |

## 3. 범위

### 1단계에 포함

- VNC 세션에서 AI가 원격 화면을 보고 마우스·키보드를 조작
- 세션 창 안의 대화 패널: 작업 지시, 진행 상황, 승인, 중단
- 사람과 AI의 조작 충돌 처리 (사람 우선)
- Claude 형식과 GPT 형식 어댑터, 각각 전용 도구 모드와 함수 도구 모드
- AI 설정 화면, API 키의 보안 저장소 보관, 연결별 사용 동의
- AI가 한 동작의 로컬 기록

### 2단계 (이 계획서에서는 방향만 정함)

- RDP 세션 지원
- Gemini 형식 어댑터
- 명령 실행 도구: 대상에 SSH로도 접속할 수 있을 때, 화면 조작과 명령 실행을 섞어 쓴다 (5.8 참고)
- 자동 재개, 작업 기록 내보내기 등 편의 기능

### 하지 않는 것

- SSH 터미널 창(HopDesk의 터미널 세션 화면)을 AI가 조작하는 기능
- 원격 PC에 보조 프로그램을 설치해 접근성 정보로 조작하는 방식 (5.8 참고)
- 로컬 컴퓨터(HopDesk를 실행하는 기기) 조작
- 사람 없이 예약 실행되는 무인 작업
- 화면 내용을 분석해 UI 요소를 찾아 주는 보조 모델(OmniParser 등) 내장

## 4. 사용 흐름

1. 사용자가 **설정**에서 AI 제공자(형식, 서버 주소, 모델, API 키)를 한 번 등록한다.
2. 연결 상세 화면에서 그 연결의 **AI 공동 작업**을 켠다. 처음 켤 때 "원격 화면의 스크린샷이 설정한 AI 서버로 전송된다"는 안내를 보고 동의한다.
3. 세션을 열면 창 오른쪽 아래에 캐릭터와 말풍선, 입력칸이 겹쳐 보인다. 전체 화면이든 창 모드든 같은 창 안에 그리므로 항상 보이고, 캐릭터를 누르면 말풍선을 접거나 편다. 오버레이는 이 기기의 창에만 그려지며 원격 PC와 AI가 받는 스크린샷에는 들어가지 않는다.
4. 패널에 작업을 적는다. 예: "제어판에서 프린터 목록을 열어 줘".
5. AI가 실행할 동작을 제안한다. 승인 모드에서는 사용자가 **실행**을 눌러야 동작한다.
6. AI가 누르려는 곳에는 번호 표시가, AI의 포인터 위치에는 링이 그려진다(원격 포인터는 이 기기의 커서와 따로 움직이므로). AI가 조작하는 동안 창 위쪽에 **AI 조작 중** 표시가 뜬다.
7. 사용자가 마우스나 키보드를 건드리면 AI는 즉시 멈춘다. 사용자가 **계속**을 누르면 AI가 화면을 다시 보고 이어간다.
8. 사용자는 도중에 추가 지시를 적거나, 중단 단축키로 작업을 끝낼 수 있다.

## 5. 구조

### 5.1 전체 그림

```text
세션 프로세스 (hopdesk connect)
 ├─ 기존: VNC 화면 수신 → 창에 표시 / 사용자 입력 → 원격 전송
 └─ 신규 agent 모듈
     ├─ capture   원격 화면 버퍼 → 축소 → PNG
     ├─ provider  형식별 어댑터 (Claude, GPT)
     ├─ action    공통 동작 타입, 좌표 환산, 키 문자열 해석
     ├─ arbiter   사람·AI 조작 중재, 승인 대기
     └─ 루프      스크린샷 → 모델 호출 → 동작 실행 → 결과 반환
```

AI 루프는 세션 프로세스 안에서 돈다. 원격 화면 버퍼와 입력 채널이 모두 그 프로세스에 있으므로, 런처와 세션 사이에 새 통신 채널을 만들 필요가 없다.

### 5.2 기존 코드와의 접점 (VNC)

| 필요한 것 | 기존 코드 | 변경 |
|---|---|---|
| 화면 픽셀 | `Screen.pixels` (RGBA, `Arc<Mutex<Screen>>`), `src/session/vnc.rs` | 전체 화면을 복사해 주는 스냅샷 함수 추가 |
| 입력 전송 | `mpsc::Sender<X11Event>` | 송신기를 복제해 agent에 전달 |
| 사람 입력 감지 | `Window::pointer`, `Keyboard::handle` | 입력이 생길 때마다 중재기에 알림 |
| 대화 패널 | 창이 egui (`eframe::App`) | `SidePanel` 추가 |
| 비동기 실행 | 세션의 tokio 런타임 | agent 루프를 같은 런타임에 띄움 |

### 5.3 공통 동작

어댑터는 제공자마다 다른 동작 표현을 아래 공통 동작으로 바꾼다. 세션 쪽은 공통 동작만 안다.

| 공통 동작 | 내용 |
|---|---|
| `Screenshot` | 현재 화면을 캡처해 돌려준다 |
| `Click { 위치, 버튼, 횟수, 보조키 }` | 좌·우·가운데 클릭, 두 번·세 번 클릭 |
| `Drag { 시작, 끝 }` | 누른 채 이동 후 놓기 |
| `MouseMove { 위치 }` | 커서 이동 |
| `Scroll { 위치, 방향, 양 }` | 휠 스크롤 |
| `Type { 글자 }` | 글자 입력 |
| `Key { 조합, 반복 }` | `ctrl+s` 같은 키 조합 |
| `Wait { 초 }` | 대기 |

좌표는 모델에 보낸 스크린샷 기준으로 오므로, 축소 비율의 역수를 곱해 원격 화면 좌표로 되돌린다. 일부 모델은 0~1000으로 정규화한 좌표를 쓰므로 설정에서 좌표 방식을 고를 수 있게 한다.

### 5.4 제공자 어댑터

```rust
trait Provider {
    /// 대화 기록과 최신 스크린샷을 보내고, 모델의 말과 다음 동작 목록을 받는다.
    async fn next(&mut self, turn: Turn) -> Result<Reply, ProviderError>;
}
```

| 형식 | 전용 도구 모드 | 함수 도구 모드 |
|---|---|---|
| Claude | `computer_toolset_20260801` (Anthropic API) | 5.3의 동작을 함수 도구로 정의 (Claude 형식 호환 서버의 오픈 모델) |
| GPT | OpenAI의 computer use 도구 (OpenAI API) | 같은 함수 도구 정의 (Ollama, vLLM 등 OpenAI 호환 서버의 오픈 모델) |

서버 주소가 제공자 본가면 전용 도구 모드, 다른 주소면 함수 도구 모드를 기본값으로 한다.

Rust용 공식 SDK가 없으므로 `reqwest`로 HTTP API를 직접 호출한다.

**Claude 형식에서 지킬 것** (2026-11-25에 공식 문서로 확인):

- 기본 모델은 `claude-opus-5-5`. 이 모델은 `computer_toolset_20260801`만 받는다.
- 한 응답에 동작이 여러 개 올 수 있다. 순서대로 실행하고, 하나가 실패하면 나머지는 실행하지 않고 정해진 문구로 응답한다.
- 모든 도구 결과에 `"toolset_name": "computer"`를 넣는다.
- 스크린샷은 긴 변 2,576px를 넘으면 거부된다. 긴 변 1280px 수준으로 줄여 보낸다.
- 한 요청의 이미지는 20장 이하로 유지한다. 오래된 스크린샷은 매 턴이 아니라 묶어서 정리한다.
- 프롬프트 캐싱을 쓰고, 진행 상황을 보여 주기 위해 스트리밍으로 받는다.
- 거부 응답(`stop_reason: "refusal"`)을 처리한다.

**GPT 형식**은 이 계획서 작성 시점에 공식 문서로 확인하지 못했다. 구현 직전에 OpenAI 공식 문서와 [openai/openai-cua-sample-app](https://github.com/openai/openai-cua-sample-app)을 확인하고 이 절을 보완한다.

### 5.5 사람과 AI의 조작 중재

원격 PC에는 커서와 키보드 포커스가 하나뿐이므로 동시에 조작할 수 없다. 규칙은 다음과 같다.

| 상황 | 동작 |
|---|---|
| AI 조작 중 사람이 마우스 버튼, 휠, 키를 입력 | AI의 남은 동작을 취소한다. 모델에는 "사용자가 개입했다"는 결과를 돌려준다 |
| 사람이 **계속**을 누름 | 새 스크린샷과 함께 루프를 재개한다 |
| 승인 모드에서 동작 묶음 도착 | 패널에 동작 목록을 보여 주고 **실행** / **거절**을 기다린다 |
| 중단 단축키 또는 **중단** 버튼 | 루프를 끝내고 눌린 키와 버튼을 모두 뗀다 |
| 세션 종료 | 루프를 끝낸다 |

AI는 동작 하나를 실행하기 전마다 취소 여부를 확인한다. 커서를 단순히 움직이는 것(버튼 없이)은 개입으로 치지 않는다. 화면을 보려고 마우스를 스치는 일이 잦기 때문이다.

### 5.6 설정과 저장

| 항목 | 위치 | 비고 |
|---|---|---|
| 형식, 서버 주소, 모델, 도구 모드, 좌표 방식 | 설정 파일 (앱 전체에 하나) | |
| API 키 | OS 보안 저장소 | 기존 `secret_store` 사용. 설정 파일에 쓰지 않는다 |
| 연결별 AI 사용 여부와 동의 | 연결 프로필 | 기본값은 꺼짐 |
| 동작 모드 (승인 / 자동) | 연결 프로필 | 기본값은 승인 |
| 한도 (작업당 최대 단계 수, 최대 토큰) | 코드의 이름 붙은 상수 | 1단계에서는 설정으로 노출하지 않는다 |

### 5.7 한글 입력

VNC 세션은 키를 자판 위치 기준으로 보내고 원격 입력기가 한글을 조합한다. AI가 한글 문장을 입력할 때는 이 방식을 쓸 수 없으므로, 기존 클립보드 경로(`X11Event::CopyText`)로 글자를 보낸 뒤 붙여넣는다. 이때 원격 클립보드 내용이 덮어써진다. ASCII 글자는 키 이벤트로 직접 보낸다.

### 5.8 화면 없이 조작하는 방법과 채택 방침

VNC와 RDP만으로는 화면 픽셀이 원격 PC의 상태를 알 수 있는 유일한 정보다. 화면 없이 조작하려면 다른 통로가 필요하다. 검토한 방법은 다음과 같다.

| 방법 | 화면 없이 가능한 일 | 조건과 한계 | 방침 |
|---|---|---|---|
| 명령 실행 (SSH, PowerShell) | 프로그램 실행, 파일 작업, 설정 변경. 결과가 글자로 돌아와 빠르고 싸고 정확하다 | 원격에 SSH 서버가 있어야 한다. GUI 프로그램 안의 버튼은 누를 수 없다. Windows에서는 SSH로 띄운 GUI 프로그램이 로그인한 사용자 화면에 보이지 않는 것이 보통이다 | **2단계에 채택** |
| 접근성 정보 (Windows UI Automation, macOS 접근성 API) | 창, 버튼, 입력란을 이름과 구조로 읽고 직접 누른다. 좌표 추측이 없어 정확하다 | 원격 PC에 보조 프로그램을 설치해야 한다. VNC와 RDP에는 이 정보를 전달하는 통로가 없다 | 채택하지 않음. "원격에 아무것도 설치하지 않는다"는 HopDesk의 전제와 어긋난다 |
| 키보드만 보내기 | `Win+R`, 프로그램 이름, Enter처럼 정해진 순서로 프로그램 실행 | 결과를 확인할 수 없다. 창이 늦게 뜨거나 포커스가 다른 곳에 있으면 엉뚱한 곳에 입력된다 | 단독으로는 쓰지 않음 |

**채택 방침은 섞어 쓰는 것이다.** 1단계는 화면 기반 조작만 구현한다. 2단계에서 명령 실행 도구를 더해, 명령으로 할 수 있는 일은 명령으로 하고 GUI 조작이 필요할 때만 스크린샷을 쓴다. 스크린샷 수가 줄어 비용과 속도가 나아지고, AI 서버로 나가는 화면도 줄어든다.

명령 실행 도구의 설계 방향은 다음과 같다.

- 연결 프로필에 같은 대상의 SSH 접속 정보가 있을 때만 켤 수 있다. 기존 점프 호스트·VPN 경로를 그대로 쓴다.
- 모델에는 화면 조작 도구와 함께 명령 실행 도구를 준다. 어떤 도구를 쓸지는 모델이 고른다.
- 명령은 화면 조작보다 영향이 크므로, 자동 모드에서도 **명령 실행은 항상 승인을 받는다.**
- 명령과 출력은 동작 기록에 남긴다.

화면 캡처를 피하려는 이유에 따라 권장하는 선택은 다르다.

| 걱정 | 권장 |
|---|---|
| 사내 화면이 외부 서버로 나가는 것 | 로컬·사내 모델을 쓴다. 화면이 사내망을 벗어나지 않는다 |
| 비용과 속도 | 명령 실행 도구를 함께 쓴다 (2단계) |

여기서 말하는 캡처는 원격 PC에서 화면을 따로 찍는 것이 아니다. HopDesk가 화면을 표시하려고 이미 받아 둔 픽셀을 쓰므로 원격 쪽에 추가 권한이나 부하가 없다. 스크린샷은 모델이 요청할 때만 전송한다.

## 6. 보안과 개인정보

HopDesk가 접속하는 대상은 자동 로그인된 실제 사내 PC다. AI 제공자들은 computer use를 격리된 환경에서 쓰라고 권고하므로, 아래 통제를 필수로 둔다.

| 위험 | 통제 |
|---|---|
| 사내 화면이 외부 서버로 전송됨 | 기본값 꺼짐. 연결별로 켜고, 처음 켤 때 전송 대상 주소를 보여 주고 동의를 받는다. 로컬·사내 모델을 쓰면 외부 전송이 없다 |
| 임의 서버 주소로 화면이 새어 나감 | HTTPS만 허용한다. HTTP는 localhost와 사설망 주소일 때만 허용한다. 대화 패널에 전송 대상을 항상 표시한다 |
| 프롬프트 인젝션 (화면의 글을 모델이 지시로 오인) | 기본값을 승인 모드로 둔다. 작업당 단계 수와 토큰에 상한을 둔다 |
| 계정 정보 노출 | 접속 비밀번호를 모델에 보내지 않는다. API 키는 보안 저장소에만 둔다 |
| AI가 무엇을 했는지 알 수 없음 | 동작마다 시각, 종류, 좌표를 로컬 로그에 남긴다. 입력한 글자 내용은 기록하지 않는다 |
| AI가 조작 중인지 모름 | 창에 **AI 제어 중** 표시를 항상 띄운다 |
| AI가 임의 명령을 실행함 (2단계의 명령 실행 도구) | 동작 모드와 무관하게 명령마다 승인을 받는다. 명령과 출력을 기록한다 |

조직 정책상 사내 화면을 외부 AI 서버로 보낼 수 있는지는 배포 전에 따로 확인해야 한다.

## 7. 작업 단계

### 진행 상황 (2026-11-25)

방향 변경: 주 사용 대상이 Windows(RDP)이고 대화 UI를 전체 화면에서도 보여야 해서, RDP를 먼저 하고 대화 패널 대신 창 안 오버레이로 바꿨다. RDP 창은 egui가 아니므로 IronRDP viewer에 "그리기 직전 덧그리기" 훅을 패치로 추가했다(`third_party/ironrdp-viewer-overlay.patch`).

| 항목 | 상태 |
|---|---|
| 공통 동작, 좌표 환산, 키 해석, 스크린샷 | 완료 (단위 테스트) |
| VNC 입력 변환 | 완료 (단위 테스트), 세션 연결은 아직 |
| Claude 어댑터, 에이전트 루프(승인·개입·중단) | 완료 (녹화 응답·가짜 화면 테스트) |
| RDP 입력 변환, 화면 캡처, 오버레이(캐릭터·말풍선·입력칸·표시) | 완료, 실제 세션 확인 필요 |
| API 키 | `hopdesk set-ai-key`로 OS 보안 저장소에 저장. 키가 있으면 모든 RDP 세션에 보조자가 나타난다 |
| AI 설정 화면 | 사이드바 **AI** 버튼. 켜기/끄기, 제공자, 모델, 키(제공자별로 OS 보안 저장소), 내 서버 주소·좌표 방식 |
| 제공자 | Claude(전용 도구), GPT(Responses API `computer` 도구), Gemini(GenerateContent `computer_use`, 데스크톱), 내 서버(OpenAI 형식 또는 Claude 형식, 함수 도구) |
| 남은 것 | 연결별 켜기/끄기, VNC 연결, 실제 세션에서 한글 입력(IME)·가로 스크롤 방향 확인, 감사 로그, GPT·Gemini 실제 호출 확인 |

제공자별로 문서로 확인하지 못한 점 (실제 호출로 확인 필요):

- GPT: 지원 모델 목록이 문서에 없어 기본 모델을 문서 예시(`gpt-6.2-sol`)로 두었다. 대화 상태는 OpenAI 쪽에 저장된다(`previous_response_id`).
- Gemini: 데스크톱 환경의 결과(`functionResponse`) 형식과 좌표 범위(0–999와 0–1000)가 문서마다 다르다. 결과는 일반 멀티모달 함수 응답 형식으로 보내고, 좌표는 1000 기준으로 환산한다. 키를 누르고 있는 동작(`key_down`/`key_up`)은 지원하지 않는다.
- 내 서버: 서버마다 도구 호출 지원 수준이 다르다. 화면 이미지는 도구 결과가 아닌 사용자 메시지로 보낸다.

### 1단계: VNC

| 순서 | 작업 | 산출물 | 검증 |
|---|---|---|---|
| 1 | 공통 동작, 좌표 환산, 키 문자열 해석 | `src/agent/action.rs` | 단위 테스트: 환산 왕복, 정규화 좌표, 키 조합 → keysym |

| 7 | AI 설정 화면, 키 보관, 연결별 토글과 동의 | `src/profile.rs`, `src/gui/form.rs`, `src/gui/detail.rs` | 설정 저장·불러오기 테스트, 주소 검증 테스트 |

### 2단계: RDP, Gemini, 명령 실행

| 작업 | 내용 |
|---|---|
| 명령 실행 도구 | 대상의 SSH 접속 정보로 명령을 실행하고 출력을 모델에 돌려준다. 기존 `russh` 연결과 터널을 쓴다. 명령마다 승인을 받는다 (5.8) |
| RDP 화면 캡처 | IronRDP viewer에 필요할 때 최신 프레임을 꺼내는 패치 추가. `third_party/PATCHES.md`에 기록 |
| RDP 입력 | `RdpInputEvent::FastPath`로 동작 전송. 글자는 유니코드 키 이벤트로 직접 보낸다 |
| RDP 사람 입력 감지 | viewer의 입력 경로에 알림 훅 패치 |
| RDP 대화 UI | 별도 보조 창. RDP 창은 egui가 아니어서 패널을 넣을 수 없다 |
| Gemini 형식 어댑터 | 공식 문서와 [google-gemini/computer-use-preview](https://github.com/google-gemini/computer-use-preview) 확인 후 구현. Gemini의 전용 도구는 브라우저 중심이라 데스크톱 조작 적합성을 먼저 시험한다 |

## 8. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 함수 도구 모드에서 일반 모델의 클릭 좌표가 부정확 | 오픈 모델로는 작업이 자주 실패 | 설정 화면에 검증한 모델을 안내하고 나머지는 "실험적"으로 표시. UI 조작용으로 학습된 모델 권장 |
| 호환 서버마다 도구 호출 지원 수준이 다름 | 특정 서버에서 동작하지 않음 | 9번 확인에서 Ollama와 vLLM을 시험하고 지원 범위를 문서에 적는다 |
| 제공자 API가 자주 바뀜 | 어댑터가 깨짐 | 어댑터를 형식별 파일로 격리. 도구 버전 문자열을 상수로 둔다 |
| 스크린샷 누적으로 비용 증가 | 긴 작업의 비용이 큼 | 축소 전송, 캐싱, 단계·토큰 상한, 패널에 사용량 표시 |
| 원격 화면이 큼 (4K 이상) | 축소 후 작은 글자를 모델이 못 읽음 | Claude 전용 도구의 `zoom`을 지원. 함수 도구 모드에도 같은 확대 동작을 둔다 |
| RDP viewer 패치가 upstream 갱신과 충돌 | 2단계 유지보수 부담 | 패치를 최소화하고 `PATCHES.md`에 근거를 남긴다 |
